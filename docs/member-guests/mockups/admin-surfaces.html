Member guests — what the admin sees

Static mockup, mock data. Three surfaces: the settings card that turns the policy knobs, the consent state on a booking, and the exception list of rows the system could not resolve on its own.

1 · The settings card

Where: Admin › Bookings setup, beside the other booking-policy cards. Per owner decision D-17 this ships in the same release as the behaviour it controls — MG1 shipped the module switch alone with "arrives in a later update" copy, so no admin can change a setting over an inert feature.

Admin › Bookings setup › Member guests

Member guests

Lets a member add another club member — outside their own family group — as a guest on their booking.

Does the other member have to agree first?
Ask them firstThe member is emailed and the bed is held until they answer. Recommended, and the default.
Just tell themThe guest is added straight away and the member is emailed to say so. They can still take themselves off.

Days, 1 to 60. After this the request lapses on its own, the bed is released, and the person who made the booking is told. A request never outlives the stay: it always lapses at least a day before check-in.

Finding the other member
Let members search by nameOff: a member must type the other member's exact email address. On: they can type a name and pick from a list.
Turning this on makes your membership list browsable. Any member can type a few letters and see the names of other members who match. Leave it off unless your club has agreed to that.
Include under-18s in name searchOff: children never appear in the name list.
Turning this on makes children's names browsable to any member. A child can still be added by their household email address either way.
These two search settings never travel in club config transfer (owner decision D-18). Importing another club's configuration must not quietly make your membership list browsable. The module switch, the ask-first choice and the waiting period do travel.

State B — an admin with view access but not manage access

Member guests

You can see these settings but not change them. Ask an administrator with booking-settings access if something here needs changing.
Does the other member have to agree first?
Ask them firstCurrently in use.
View-only is a real third state, not a disabled second one. The card reads its own permission and renders read / write / no-access distinctly, so an admin is never shown a Save button that will 403.

2 · Consent state on a booking

There is no separate admin booking-detail page in this app — an admin reads the member booking page with admin tools — so the badge lives on the guest list there, and the same badge is what the member sees. Family and non-member guests get no badge at all.

Four reasons reach this list, and only four: the guest is the booking's last one; the booking was quote-priced by hand; the booking is in a status that forbids guest changes; or check-in has already happened. Everything else — including every ordinary paid booking — resolves without an admin. The nightly sweep counts these separately from the ones it settled, so a growing number is visible in the background-jobs health view rather than buried.
